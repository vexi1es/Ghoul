# Launch Lab 21 — идея проекта (по регламенту турнира)

## Одним абзацем
Платформа инкубатора Launch Lab 21, где команда стартапа проходит программу по модулям, отвечает на вопросы по шаблону, и из её ответов **автоматически собирается one-pager**. Наша фишка: one-pager — не мёртвый документ, а **живая карточка стартапа в общей галерее инкубатора**. Статус проекта (💡 Идея → 🔨 MVP → 🚀 Готов к инвестициям) считается сам из прогресса по модулям. В галерее пиры, кураторы и инвесторы видят все команды, оставляют отзывы, а команда прямо в one-pager показывает, кого ищет в команду и сколько нужно денег.

## Как наша идея легла на регламент
| Что мы хотели | Как это живёт в регламенте |
|---|---|
| Главная с карточками стартапов | Необязательная фича «Общая галерея one-pager всех команд для Demo Day» — делаем её нашей главной |
| Стадии: Идея → MVP → Инвестиции | Стадия **вычисляется** из количества пройденных модулей. Ничего руками не выбирается |
| Профиль стартапа: команда, описание | Обязательный «Профиль проекта: название, состав команды, краткое описание» |
| Вакансии, «ищем в команду» | Поле в модуле «Команда и ресурсы» → блок «Ищем в команду» в one-pager |
| Инвесторы видят, кому нужны деньги | Поле «Сколько нужно и на что» → блок «Инвестиции» в one-pager; фильтр «🚀 Готовы к инвестициям» в галерее |
| Отзывы и идеи | Необязательная фича «Комментарий куратора» — расширяем: комментарий может оставить любой, кто открыл one-pager из галереи |
| Два типа профиля (dev / инвестор) | Заменяем на **переключатель роли** в шапке: Участник / Куратор / Гость. Без авторизации — регламент прямо говорит, что роли не входят в минимум |

## Что строим (обязательный минимум — сначала)
**Обязательный сценарий, который должен работать целиком:**
Создать/открыть проект → пройти модуль → сохранить ответ → увидеть его в one-pager.

1. **Профиль проекта** — название, команда (список имён), краткое описание.
2. **Модули программы** — идут по порядку, видно пройденные и текущий:
   - Модуль 1 «Проблема и аудитория»: какую проблему решаете · кто от неё страдает · как справляются сейчас
   - Модуль 2 «Решение и MVP»: что за продукт · ключевая функция · что уже сделано
   - Модуль 3 «Рынок и первые клиенты»: кто первые клиенты · как до них дотянуться · аналоги и чем мы лучше
   - Модуль 4 «Команда и ресурсы» *(наш, добавляем, когда 1–3 работают)*: кто в команде и кто за что отвечает · кого ищем (роли) · сколько нужно денег и на что
3. **Шаблоны ответов** — у каждого поля placeholder-подсказка.
4. **Сохранение** — всё в LocalStorage, переживает перезагрузку.
5. **Прогресс** — «2 из 4 модулей», прогресс-бар.
6. **One-pager** — собирается сам: название, команда, описание, блок на каждый модуль. Незаполненный модуль показывается как **честный пустой раздел** «Модуль не заполнен», а не прячется.

## Что добавляем сверху (только когда минимум работает целиком)
Порядок строго по ценности для жюри:
1. **Стадия проекта** — бейдж на one-pager и в галерее: 0–1 модуль = 💡 Идея, 2–3 = 🔨 MVP, все 4 = 🚀 Готов к инвестициям. Три строчки кода, жюри видит «умную» систему.
2. **Галерея Demo Day** — экран со всеми проектами карточками: название, стадия, прогресс, команда, «ищем: frontend, дизайнер». Фильтр по стадии. Клик → one-pager. Это наша «витрина стартапов».
3. **Режим куратора** — переключатель роли в шапке. Куратор видит галерею с прогрессом каждой команды, открывает ответы, оставляет комментарий к модулю. Участник видит только свой проект.
4. **Комментарии на one-pager** — любой в роли Гость/Куратор оставляет отзыв. Хранятся в том же LocalStorage.
5. **Печать / PDF** — кнопка `window.print()` с print-стилями. Бесплатно.
6. **Визуал** — в самом конце. Стиль School 21: тёмный фон, зелёный акцент, моно-шрифт в заголовках.

Если время горит — режем снизу вверх. One-pager не режется никогда.

## Модель данных (в LocalStorage, один ключ `ll21`)
```
{
  role: "member" | "curator" | "guest",
  currentProjectId: "p1",
  projects: [
    {
      id, title, team: ["Sodirxon", "Anna"], description,
      answers: { m1: { q1: "...", q2: "...", q3: "..." }, m2: {...} },
      comments: [ { id, moduleId|null, author, text, createdAt } ],
      updatedAt
    }
  ]
}
```
Модули — **константный массив** в коде, экраны строятся из него динамически, ничего не хардкодится:
```
modules = [ { id: "m1", title, fields: [ { id: "q1", label, placeholder } ] }, ... ]
```
Стадия = функция от `answers`, не хранится. Прогресс = функция от `answers`. Всё вычисляется, ничего не дублируется — это и есть «работа с данными», которую оценивают.

Сид-данные при первом запуске: **один заполненный проект** (наш, чтобы показывать красивый one-pager) и **один пустой** (для живой проверки «пустой раздел»).

## Роли в команде (3 человека, один клиентский проект)
Бэкенда нет, поэтому делим не «бэк/фронт», а по экранам и по файлам, чтобы не мешать друг другу:

| Кто | Зона | Файлы |
|---|---|---|
| **Sodirxon** (данные + ядро) | массив модулей, store поверх LocalStorage (load/save/getProject/saveAnswer), вычисление стадии и прогресса, сид-данные, экран списка модулей и форма модуля | `data.js`, `store.js`, `ModuleList`, `ModuleForm` |
| **Фронт 1** | one-pager (сборка из answers, пустые разделы, print-стили), профиль проекта | `OnePager`, `ProjectProfile` |
| **Фронт 2** | галерея Demo Day, переключатель роли, режим куратора, комментарии, общий layout/визуал | `Gallery`, `RoleSwitch`, `Comments`, `App` layout |

Интерфейс между зонами — только `store.js`: `getProjects()`, `getProject(id)`, `saveProject(p)`, `saveAnswer(projectId, moduleId, fieldId, value)`, `getStage(project)`, `getProgress(project)`. Договариваемся о нём в первые 5 минут и не меняем.

## Тайминг (по регламенту, с нашими вставками)
| Время | Что |
|---|---|
| 00:00–00:10 | Sodirxon: модули массивом + store + сид. Фронты: каркас App с роутингом по экранам, пустые компоненты |
| 00:10–00:30 | Форма модуля → save → one-pager показывает ответ. **Здесь выдыхаем — результат есть.** Живая проверка: F5, ответ на месте |
| 00:30–00:45 | Модули 2–4 в массив, прогресс-бар, стадия, галерея с карточками |
| 00:45–00:55 | Одно из: куратор + комментарии **или** визуал. Не оба |
| 00:55–01:00 | Три живые проверки из регламента. Сдать в бот + историю чатов. Код не трогать |

## Три живые проверки — прогоняем на 55-й минуте
1. F5 — введённый ответ на месте.
2. Жюри называет фразу → вписываем в поле модуля → открываем one-pager → фраза там.
3. Открываем пустой проект → one-pager показывает пустые разделы, вёрстка не ломается.

## Питч (3 минуты)
- **Проблема (30с):** команды в инкубаторе заполняют задания по модулям, а потом отдельно, ночью перед Demo Day, пишут one-pager. Дважды одна работа, и он всё равно устаревает.
- **Демо (2 мин):** открыть проект → заполнить модуль (фраза от жюри) → сохранить → F5 → one-pager с фразой и бейджем стадии → галерея Demo Day: все команды, фильтр «🚀 готовы к инвестициям», «ищем в команду» → переключить роль на Куратора → комментарий → открыть пустой проект → честные пустые разделы.
- **Почему лучше (30с):** one-pager у нас не документ, а живая карточка: стадия считается сама, галерея — это Demo Day круглый год, и любой пир или инвестор может найти команду, которой нужен именно он.

## Про правила, о которых важно помнить
- Всё пишется после старта таймера с чистого листа. Этот документ — чтобы **держать идею и структуру в голове**, а не чтобы вставлять в чат.
- История переписки с AI сдаётся жюри и оценивается отдельно (декомпозиция задач, как чиним баги). Промпты — короткие, по одному, «логику не трогай».
- Не просить ИИ чинить баг, который он только что создал: откат, новый чат, задача иначе.
- Ноутбук для демо назначить заранее, HDMI, крупный шрифт.
- Запасные аккаунты LLM — лимиты сгорают быстро.
